# @gcsim/editor

## Purpose

CodeMirror 6 editor with custom gcsim language support. Provides syntax highlighting, autocomplete, error diagnostics, and a controlled React wrapper component.

## Architecture

The editor uses a **minimal Lezer grammar** that only tokenizes (no statement/expression rules). All real parsing and validation is delegated to the Go WASM parser via `executor.validate()`.

Key design decisions:
- **Grammar is token-level only** — `@top Program { expression* }` with flat token alternation
- **External specializer** classifies identifiers as characters, actions, stats, or elements at runtime
- **Autocomplete is text-based** — uses `matchBefore()` and regex, not the syntax tree
- **Diagnostics are independent** — errors from WASM validation applied via `setDiagnostics`
- **All features work independently** — highlighting, autocomplete, diagnostics, folding

## File Structure

```
src/
├── index.ts                     # Public barrel exports
├── language/
│   ├── gcsim.grammar           # Lezer grammar source (hand-written)
│   ├── parser.ts               # Generated parser tables (DO NOT EDIT)
│   ├── parser.terms.ts         # Generated term IDs (DO NOT EDIT)
│   ├── tokens.ts               # External specializer (hand-crafted, TODO: codegen)
│   ├── gcsim-language.ts       # LRLanguage + LanguageSupport
│   ├── autocomplete.ts         # Context-aware CompletionSource
│   └── fold.ts                 # Brace-matching fold service
├── diagnostics/
│   └── diagnostics.ts          # setDiagnostics wrapper for GcsimError
├── theme/
│   └── dark-theme.ts           # Catppuccin-inspired dark theme
└── components/
    └── editor.tsx              # Controlled React wrapper
```

## How to Modify

### Adding new keywords to syntax highlighting

1. If it's a **domain token** (character, action, stat, element): add to the appropriate `Set` in `src/language/tokens.ts`
2. If it's a **language keyword** (like `let`, `if`): add via `@specialize` in the grammar, then add to `styleTags` in `gcsim-language.ts`
3. Rebuild grammar: `pnpm run build:grammar`

### Adding new autocomplete entries

Edit `src/language/autocomplete.ts` — add to the appropriate completion array (`actionCompletions`, `statCompletions`, `characterCompletions`, `keywordCompletions`).

### Changing the theme

Edit `src/theme/dark-theme.ts`. The `gcsim-dark` theme reads from the
`ui-next` design-system CSS variables (`--bg-0/1/2`, `--fg-0/1/2/3`,
`--line-1/2`, `--accent`, `--accent-soft`, `--warn-soft`, the
`--el-*` element hues, `--brand-blue-2`, `--font-mono`). The
JSDoc block at the top of the file documents which token drives each
surface. Never hard-code hex colours — always use `var(--token)`.
`gcsimDarkTheme` controls editor chrome (gutters, background, cursor).
`gcsimHighlightStyle` controls syntax token colors.

## Public API

```typescript
import { Editor, gcsim, applyDiagnostics, clearDiagnostics, gcsimDarkTheme } from "@gcsim/editor";
import type { EditorProps, EditorParseStatus, EditorTab, GcsimError } from "@gcsim/editor";
```

- **`Editor`** — Controlled React component. Core props: `value`, `onChange`,
  `readOnly`, `errors`, `className`, `fontSize` (default `14`, applied via
  a CodeMirror Compartment so it can be re-configured live),
  `onFontSizeChange`, `theme` (only `'gcsim-dark'` ships).
  Optional chrome props (rendered only when `showChrome` is `true`):
  `tabs`, `activeTab`, `onTabChange`, `onFormat`, `parseStatus`
  (`'ok' | 'parsing' | 'error' | 'idle'`, maps to a `<StatusPill>`),
  `optionsBadges` (right-aligned ReactNode slot in the footer).
  When `showChrome` is false (default), the component renders only the
  CodeMirror surface — existing call sites are unaffected.
- **`gcsim()`** — `LanguageSupport` extension for standalone CM6 usage
- **`applyDiagnostics(view, errors)`** — Push WASM validation errors to editor
- **`clearDiagnostics(view)`** — Remove all diagnostics
- **`gcsimDarkTheme`** / **`gcsimHighlightStyle`** — Theme extensions

## Generated Files

`parser.ts` and `parser.terms.ts` are generated by `@lezer/generator` from `gcsim.grammar`. They are committed to git so consumers don't need the generator. Regenerate with:

```bash
pnpm run build:grammar
```

These files are excluded from biome linting (configured in root `biome.json` overrides).

## Dependencies

- `@codemirror/*` — Editor framework (view, state, language, autocomplete, lint, search, commands)
- `@lezer/*` — Parser runtime (lr, common, highlight)
- `@lezer/generator` — Dev dependency for grammar compilation

## Testing

Tests use Vitest + jsdom. Grammar tests verify tokenization without DOM. Component tests use Testing Library.

Run tests: `pnpm test` or `npx turbo run test --filter=@gcsim/editor`

## Don'ts

- Don't edit `parser.ts` or `parser.terms.ts` — they are generated
- Don't add statement/expression rules to the grammar — the Go WASM parser handles validation
- Don't import from internal paths — use `@gcsim/editor` barrel export
- Don't use the syntax tree for autocomplete — use text-based analysis
